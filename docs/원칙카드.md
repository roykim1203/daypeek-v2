# 원칙 카드 (5칸) — DayPeek

> 고친 원칙마다 한 장. P번호 = 닐슨 원칙 번호이며 디자인 가이드(`docs/디자인가이드.md` 2장) · 코드 주석(`// A-5 P01`) · 영상(`docs/영상/p01.mp4`) · 셀프 논증(`docs/셀프논증.md`)과 같은 번호를 씁니다.
> '판단' 칸은 셀프 논증 기록의 "내 주장 → 반론 → 재반론 → 결론 → 근거"를 줄여 쓴 것입니다.
>
> **표시 규칙**: `[원본 증거 삽입 필요]` = 리뷰 원문 · 캡처 · 영상처럼 아직 붙이지 못한 증거. 임의로 채우지 않았습니다.
> 현행 앱 근거는 **서로 다른 두 사례**입니다 (`docs/기획.md` 1-2).
> - **사례 A — 기존 직접 테스트 기록**(캡처 없음): 2026-10-28, 같은 날짜에 일정 5개 → 월간 화면 글자 '작게' 3개 · '보통' 2개 · '아주 크게' 2개, 날짜를 선택하면 5개 모두. 작성자 기기의 특정 환경에서의 기록이며 모든 기기에서 같다는 주장은 아닙니다.
> - **사례 B — 실제 스크린샷**: 2026-10-29, 일정 6개 → 월간 화면 3개 · (글자가 더 큰 캡처) 2개, 날짜 선택 후 6개. 캡처에 글자 크기 설정 이름은 표시되지 않습니다.
> - DayPeek 캡처는 **가상 데이터(2026-10-28, 일정 5개)를 쓰는 별도 시연**이며, TimeTree의 실제 데이터를 불러온 것이 아닙니다.
> DayPeek 화면 A의 글자 크기 메뉴(A-9)는 DayPeek 자체 3단계('작게' · '보통' · '크게')입니다 — 현행 앱의 설정 이름과 다릅니다.
> '판단' 칸의 대안 비교 중 작성자가 직접 밝힌 이유는 `(작성자)`로 표시했고, 나머지는 개발 기록을 바탕으로 AI가 정리한 초안입니다 — 작성자 확인 필요.
