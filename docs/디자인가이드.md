# 디자인 가이드 — DayPeek (TimeTree v2)

> 기획 5단계 "화면 기획"(발표자료 부록 B5 화면별 요소 분석표)의 요약본입니다. **코드의 화면 파일 맨 위 대응표와 번호·명칭이 같아야** 합니다(UI 25점 "기획과 일치").
> 이 가이드에 없는 화면은 만들지 않습니다(감점). 화면을 바꾸면 여기 → 코드 대응표 → 원칙 카드 순서로 같이 고칩니다.
> 회색 예시(템플릿의 A·B·C)는 내 화면으로 바꿔 씁니다.

## 1. 화면 목록과 흐름

| 화면 | 이름(비즈니스 명칭) | 파일 | 들어오는 방식 | GET |
|---|---|---|---|---|
| A | 월간 달력 (`MonthCalendarScreen`) | `lib/screens/a_list_screen.dart` | 첫 화면 | `/schedules?date_like=2026-10` |
| B | 하루 전체 일정 (`DayScheduleScreen`, 하루 일정 패널 `DaySchedulePanel`) | `lib/screens/b_detail_screen.dart` | 쌓기(`Navigator.push` + `PageRouteBuilder` · 아래에서 올라오는 `SlideTransition`) — A에서 날짜 칸 또는 `+N개` 배지 누름 | `/schedules?date=…&_sort=start` · `/notes?date=…&_sort=time` ('하루 메모' 탭) |
| C | 일정 상세 (`ScheduleDetailSheet`) | `lib/screens/c_result_sheet.dart` | 덮기(modal) — B에서 일정 한 줄 누름 | 없음(B에서 넘긴 일정) |

```
A 월간 달력 ──쌓기(push: 날짜 칸 · +N개 배지, 아래에서 올라오는 패널)──▶ B 하루 전체 일정 [옆으로(tab): 일정 | 하루 메모] ──덮기(modal: 일정)──▶ C 일정 상세
```

- AI 예시는 B '일정' 탭 맨 위 **B-9 AI 하루 브리핑(예시)** 한 곳에만 있다(하루 전체 개수 · 오전/오후/저녁 흐름). 날짜별로 미리 작성한 하드코딩 문장이며 실제 AI 호출 · 실시간 생성은 없다.

- B는 화면 전체를 덮지 않고 아래에서 올라오는 패널(높이 92%, 위 모서리 둥글게, 손잡이)이며 뒤의 A는 반투명하게 어둡게 보인다. 닫기: ✕ · 뒤로 가기 · 손잡이 아래로 끌기 · 어두운 바깥 누르기 → A로 `pop`.

- 전환 3방식: **쌓기**(push/pop) · **옆으로**(tab) · **덮기**(modal) — 흐름도의 화살표마다 하나를 적는다.
- 적응형: A의 날짜 칸 높이 = 남은 높이 ÷ 줄 수 — `LayoutBuilder`. 창 너비 **600dp 미만**은 항상 **6주 격자**(앞뒤 달 날짜 흐리게, 칸 최소 88dp), **이상**은 그달의 주만(10월 = 5주, 칸 최소 120dp, 최대 너비 1000dp). 칸이 커지면 보이는 일정 수가 늘고 `+N개`가 줄어든다(같은 표시 계산).
- 공통 테마(S-2): 흰 바탕 + DayPeek 브랜드 색(청록 `#2A9D8F` 기반 Material 3 색). 앱 이름·브라우저 탭 'DayPeek'(S-1).
- 핵심 데모 날짜: **2026-10-28(수)**, **가상 일정 5개**(`mock_server/db.json`) — TimeTree 실제 데이터가 아닌 별도 시연. 현행 TimeTree 사례 A(직접 테스트 기록, 2026-10-28, 일정 5개: 글자 '작게' 3개 · '보통' 2개 · '아주 크게' 2개)의 날짜 · 개수를 본떠 만들었다. 실제 스크린샷이 있는 사례 B(2026-10-29, 일정 6개)는 `docs/기획.md` 1-2. (DayPeek 글자 크기 메뉴 A-9는 자체 3단계 '작게' · '보통' · '크게'.)

## 3. 요소 분석 (화면마다 한 표 — 코드 대응표와 같은 번호)

### 화면 A — 월간 달력

위젯 트리 (코드 `a_list_screen.dart` 대응표와 같은 번호):

```
MonthCalendarScreen (StatefulWidget)
└─ Scaffold
   ├─ A-1 AppBar  왼쪽 굵은 '2026년 10월' | 오른쪽 이전·다음 달 IconButton(→ SnackBar) + A-9 글자 크기 PopupMenuButton
   └─ FutureBuilder<List<Schedule>>  (GET /schedules?date_like=2026-10)
      ├─ A-6 LoadingView '달력을 불러오는 중…'
      ├─ A-7 ErrorView + '다시 시도'
      ├─ A-8 EmptyView '이번 달 일정이 없습니다.'
      └─ LayoutBuilder (600dp 분기 → 줄 수 6주 / 그달 주)
         ├─ A-2 WeekdayHeader  Row × 7 (일 빨강 · 토 파랑) + 아래 구분선
         └─ Expanded → LayoutBuilder (칸 높이 = 남은 높이 ÷ 줄 수)
            └─ A-3 날짜 칸 격자  Row(주) × 7
                  ├─ OutsideDayCell  앞뒤 달 날짜 (흐린 숫자, 누를 수 없음)
                  └─ DayCell = Semantics + Material(선택 배경) + InkWell + LayoutBuilder
                     ├─ A-10 DateMark  날짜 숫자 (오늘: 진한 원 · 선택: 테두리 원)
                     ├─ A-4 SchedulePill × 보이는 개수  (캘린더 색 채움 + 대비 높은 글자색 · 1줄 말줄임)
                     └─ A-5 HiddenCountBadge '+N개 ›'  (N > 0일 때만, 자리 먼저 확보, 칸 너비 전체, 누르면 B)
```

## 4. 디자인 가이드 글 (위에서 정의한 명칭을 그대로 쓴다)

### 숨겨진 일정 수 표시 (A-5)
- **목적**: 월간 달력 날짜 칸에 다 들어가지 않은 일정이 몇 개인지 날짜를 누르기 전에 알려 준다.
- **내용**: 칸 맨 아래 한 줄에 `+N개`(N = 하루 일정 총개수 − 보이는 일정 수). 2026-10-28 일정 5개 기준으로 3개가 보이면 `+2개`, 2개가 보이면 `+3개`, 모두 보이면 배지를 그리지 않는다. 보이는 개수는 칸 높이와 글자 크기로만 정하는 **표시 계산**이다(정렬·우선순위 같은 비즈니스 로직 없음).
- **의도**: P01 시스템 상태의 가시성. 현행 TimeTree 사례 A(직접 테스트 기록, 2026-10-28, 작성자 기기의 특정 환경)에서 일정 5개 중 글자 '작게' 3개, '보통' 2개, '아주 크게' 2개만 보였고 숨은 개수 안내가 없었다. 사례 B 실제 캡처(2026-10-29, 일정 6개)에서도 [월간 칸 3개](<screenshots/일정 5개 중 3개가 보이는 모습.jpg>)만 보이고 숫자 안내가 없다. 실제 Google Play 리뷰(★5, 2026-06-21, 작성자 이름 지움): "하루 일정표가 4개를 넘어가면 날짜를 눌러서 확인하기 전까지는 모르겠더라고요 … 옆에 작게 +2 이런식으로라도 알려주면 훨씬 편할 것 같아요". DayPeek 시연(가상 데이터): [화면 A `+3개`](<screenshots/화면 A.png>).

### 일정 제목 미리보기 (A-4)
- **목적**: 날짜를 열지 않고도 그날 무슨 일정이 있는지 알아보게 한다.
- **내용**: 시작 시간 순서(서버 `_sort`)대로 앞에서부터, 캘린더 색으로 채운 막대 + 제목 1줄 말줄임. 글자색은 흰색·진회색 중 막대 색과 대비가 큰 쪽(예: 주황 `#E65100` 위에는 진회색).
- **의도**: P06 기억보다 재인.

### 하루 일정 목록 (B-4)
- **목적**: 월간 달력에서 숨겨졌던 일정까지 그날 일정을 한 번에 모두 보여 준다.
- **내용**: 시작 시간순(서버 `_sort=start`)으로 전부. 한 줄에 시간(시작·끝) · 캘린더 구분 색 띠 · 일정 제목 · 캘린더 이름 · 장소. 위에 하루 일정 개수 요약(B-3) '일정 5개 · 시간순'.
- **의도**: P02 실세계 일치(다이어리 읽는 순서) · P01(A의 `+N개`와 개수가 맞음을 확인). 일정을 누르면 화면 C(일정 상세)로.

### AI 하루 브리핑(예시) (B-9)
- **목적**: AI 활용 기회를 "일정 하나 다시 요약"(화면에 이미 있는 정보와 중복)에서 "**하루 전체 흐름 브리핑**"으로 옮겼다. 일정이 많은 날 목록을 다 읽기 전에 하루가 어떻게 흘러가는지 알려 준다 — 숨겨진 일정 문제(A-5)와 같은 사용자 문제에 맞춘 위치.
- **내용**: '일정' 탭 맨 위에 접힌 카드. 펼치면 전체 개수 한 줄 + 오전(~12시) · 오후(12~18시) · 저녁(18시~) 일정 흐름 + 고지 '※ 실제 AI 호출이 아닌, 미리 작성된 시연용 브리핑입니다.' 2026-10-28은 '일정 5개 · 오전 2개, 오후 2개, 저녁 1개로 이어지는 하루' / 오전 09:00 전공 수업 → 11:00 스터디 모임 / 오후 13:00 점심 약속 → 15:00 팀 프로젝트 회의(회의실 B) / 저녁 19:00 운동.
- **데이터**: `b_detail_screen.dart`의 `demoBriefings` 하드코딩 상수(10/02 · 10/07 · 10/13 · 10/20 · 10/28 · 10/29). db.json 일정과 손으로 맞춰 썼고, 위젯 테스트가 db.json과 개수 · 시간 · 제목이 맞는지 대조한다. 실제 AI API · 실시간 생성 · 외부 날씨 API · 상태관리 패키지 없음.
- **의도**: P01 가시성 · P10 도움말(시연용 예시임을 숨기지 않음).

### 글자 크기 미리보기 (A-9)
- **목적**: 현행 앱에서 글자 크기 설정('작게' 3개 · '보통' 2개 · '아주 크게' 2개)에 따라 보이는 일정 수가 달라졌던 상황을 DayPeek 자체 3단계 메뉴('작게' · '보통' · '크게')로 데모에서 바로 보여 준다.
- **내용**: AppBar 메뉴에서 3단계 선택 → 달력 글자만 바뀐다. 저장하지 않으며 앱을 다시 열면 '보통'.
