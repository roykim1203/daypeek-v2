|---|---|
| 테스트 날짜 | 2026-10-28(수) |
| 조건 | 같은 날짜에 일정 5개 등록 |

**DayPeek 시연과의 관계**: DayPeek 프로토타입은 **2026-10-28의 가상 일정 5개**(`mock_server/db.json`)를 쓰는 **별도의 시연**입니다. TimeTree의 실제 데이터를 불러온 것이 아니며, 사례 A의 날짜 · 개수를 본떠 만든 가상 데이터입니다.

**해석**: 두 사례 모두 일정 데이터가 사라지는 **데이터 누락 문제가 아니다** — 날짜를 선택하면 모두 있다(사례 A 5개 · 사례 B 6개). 문제는 **월간 화면에서 "이 날 일정이 몇 개 더 있는지"를 알기 어렵다**는 정보 표시(UX) 문제다. 두 사례 모두 글자를 키우면 보이는 개수가 3개에서 2개로 줄었다.

## 5. 피쉬본 (원인 분석 6관점) 【작성자 가설 — 현행 앱 내부 구현은 확인 불가】

**결과(머리)**: 월간 화면에서 숨겨진 일정 수를 알 수 없다

| 관점 | 추정 원인 |
|---|---|
| 모바일 UX | 휴대폰 너비에 7열 격자 → 칸 높이가 작음 · 칸에 들어가는 줄 수가 글자 크기에 따라 줄어듦 |
| 사용성 | 숨은 일정이 있다는 신호 · 개수가 없음 → 사용자가 날짜를 눌러 보기 전까지 모름 (리뷰 R5가 같은 내용을 지적) |
| 데이터 | 하루 일정 수에 상한이 없음(공유 캘린더는 여러 사람이 추가) → 바쁜 날일수록 더 많이 숨음 |
| API | (데이터는 정상 — 날짜를 누르면 5개 모두 나옴) 월간 화면이 날짜별 개수를 표시에 쓰지 않음 |
| 네트워크 | 해당 없음에 가까움 — 직접 테스트에서 일정은 모두 불러와짐 |
| 프로세스 | 월간 화면 설계가 "칸에 들어가는 만큼 보여 주기"에 맞춰져 있고 "안 들어간 것 알리기" 단계가 없음 |

**우선순위 1개**: 사용성 — "숨은 일정 수 신호 없음" (데이터 · 네트워크는 정상이므로 표시 계층에서 해결 가능)

## 6. 5 Why (우선순위 원인 → 근본 원인)

| 단계 | 질문 | 답 |
|---|---|---|
| Why 1 | 왜 사용자가 바쁜 날의 일정을 놓칠 수 있는가? | 월간 화면에 하루 일정 일부만 보이기 때문 — 사례 A【직접 테스트】 5개 중 '작게' 3개 · '보통' · '아주 크게' 2개, 사례 B【캡처 확인】 6개 중 3개 · 2개 |
| Why 2 | 왜 일부만 보이는가? | 날짜 칸 높이가 정해져 있고, 일정 제목 한 줄의 높이는 글자 크기에 따라 커지기 때문 |
| Why 3 | 왜 숨은 일정이 있다는 걸 모르는가? | 칸에 "몇 개가 더 있다"는 개수 표시가 없기 때문 【직접 테스트 · 캡처 확인】 · 리뷰 R5 |
| Why 4 | 왜 개수 표시가 없는가? | 칸 공간을 모두 일정 제목에 쓰고, 알림 표시를 위한 자리를 따로 남기지 않는 배치이기 때문 【작성자 가설】 |
| Why 5 (근본) | 왜 그런 배치인가? | 월간 화면의 목표를 "많이 보여 주기"로만 두고, "보이지 않는 정보의 존재를 알리기"(P01)를 목표로 두지 않았기 때문 【작성자 가설】 |

**근본 원인 → v2 해결 원칙**: 칸 안에 **숨김 배지 자리를 먼저 확보**하고, 남은 공간에 들어가는 만큼만 일정을 그린 뒤 나머지 수를 `+N개`로 표시한다 (A-5, `visibleScheduleCount`).
